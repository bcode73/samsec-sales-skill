# SamCart API Reference

Curated verbatim capture of the official "SamCart Public API" OpenAPI spec (version 1.0.0) plus the Notify URL webhook docs. The API is **read-mostly**: it reports on orders/charges/customers/subscriptions and can refund charges, cancel/update subscriptions, and add products to existing orders — it does NOT create products or checkout pages.

## API basics (verbatim from the spec)

> Welcome to SamCart's Public API. This API is used for accessing the data inside your SamCart marketplace.
> **Private Beta** — This API is currently in private beta. If you would like to be considered for our beta program, please contact support@samcart.com.
> API keys can only be generated by the SamCart Support team.
> To be successfully authenticated, you must pass the header parameter `sc-api` with your provided API key. If your key is invalid or not supplied in the call, the API will return code `401 Unauthorized`.
> Along with the `sc-api` header, an `Accept` header needs to be set. This should be set to `application/json`.
> This API will accept HTTPS or HTTP requests, but HTTP requests will result in a `301 Moved Permanently`.

Base URL: `https://api.samcart.com/v1`

Quick-start cURL:

```bash
curl "https://api.samcart.com/v1/products?limit=10" \
  -H "sc-api: $SAMCART_API_KEY" \
  -H "Accept: application/json"
```

### Rate limiting (verbatim)

> All endpoints of this API are rate-limited. If any of the limits configured is reached, the service will return status code `429 Too Many Requests` to the client. If a request is rate-limited, the response will include a header explaining the limits and how many seconds are remaining before additional requests can be made.

(No numeric limits are published — read the 429 response header and back off for the stated seconds.)

### Pagination (verbatim)

> When making a request to a paginated endpoint, the response will return a maximum of 100 results but can be adjusted using the `limit` query parameter. Included in the body of the response are links to subsequent pages of results.

Paginated bulk endpoints: Charges, Customers, Products, Refunds (plus Orders and Subscriptions per the changelog). Pagination object:

```json
{
  "next": "https://example.samcart.com/v1/example?offset=1337&dir=next",
  "prev": null
}
```

Follow `next` until `null`. Bulk endpoints accept `created_at_min` / `created_at_max` filters (ISO 8601/RFC 3339, e.g. `2025-01-16T14:30:00Z`; date-only values expand to 00:00:00 / 23:59:59 UTC), and subscriptions add `canceled_at_min`/`canceled_at_max`.

### Response codes (verbatim list)

`200 Success` · `301 Moved Permanently` · `401 Unauthorized` · `404 Object could not be found` · `409 Conflict` · `429 Too Many Requests` · `504 Timeout`

## Webhooks ("Notify URL" via the Integration Engine)

Setup is UI-driven: **Apps → search "Webhooks" → Install → enter your HTTPS endpoint**, then create **Rules** (global or per-product) choosing an action ("Send NotifyURL Post", "…for Orders", "…for Courses") and a trigger.

### Triggers (from the help docs)

- Checkout charged / **Checkout failed** ("This trigger has a built-in 10-minute delay before it fires" — allows automatic retries)
- Product purchased / refunded / partially refunded
- Prospect created (fires ~2 hours after creation) / Lead added
- Subscription: charged, failed, canceled, delinquent, recovered, restarted, completed
- Course: student added / removed / started / finished

### Payload (example from help docs)

```json
{
  "type": "Order",
  "product": { "id": 10, "name": "Test", "price": 25 },
  "customer": { "first_name": "Brian", "last_name": "Moran", "email": "bri@samcart.com" },
  "order": { "id": 12412041, "total": 25 }
}
```

Missing values are sent as `NULL`.

### Security & reliability

- **No payload signing is documented** (no HMAC header). Verify authenticity by: putting an unguessable token in the endpoint path/query (`https://example.com/hooks/samcart?t={random}`), and re-fetching the referenced order/subscription via the API (`sc-api` key) before acting on a payload.
- **No retry policy is documented** beyond the checkout-failed delay. The Integration Engine keeps a log of the **last 1,000 integration events** (Configuration/Action logs) — reconcile against `GET /orders` polling for anything business-critical.

## Gaps

- API is **private beta**: keys are issued by support (support@samcart.com) — there is no self-serve key generation; plan integration timelines around that.
- No numeric rate limits published; no webhook signing or retry documentation.
- The API cannot create/update products, pages, or checkouts — those are UI-only (use Zapier/Make for action-side automation).
- Full request/response models: `https://developer.samcart.com/specs/openapi.yaml`.
